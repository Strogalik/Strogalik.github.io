# TMS V6 B10 — Calculator Studio

Дата проверки: 12 октября 2026. Статус: `awaiting_owner_review`; `stageBStarted:true`; `faqPromotion:true`; `publicDeploy:false`.

## Результат

B10 работает на основной локальной главной: http://127.0.0.1:3200/#calculator. Переработан только desktop-калькулятор. Общая оболочка ограничена 1200 CSS px; области ввода и результата — 47/53%. Один общий слой матирования, светлая кромка и мягкая тень, плотный дисплей результата, компактные равные сегменты с hit-area 44 px. Новый материал включается только от 901 CSS px; ниже используется прежняя B9.

H2 и окно имеют общую левую ось. Между ними 28 px. Верхний интервал зависит только от высоты viewport: 24–64 px, без центрирования раскрытого содержимого. На просторном экране от реальной шапки до H2 около 64 px, на 1440×900 — 51 px, на 1366×650 — 33,5 px. Исходная секция теперь естественной высоты; следующая секция может появляться на просторном экране.

В обычных закрытых режимах B9 intrinsic-reserve сохранён. В записи desktop на 401 фактически собранном кадре сдвиг H2, высоты окна и начала следующей секции при baseline-switch равен 0 CSS px. При раскрытии H2 и верх окна сохраняются, низ растёт в обычном потоке. На широком экране базовая оболочка 447,78125 px, дополнительные параметры дают +133,984375 px, оба раскрытия +472,328125 px; закрытие возвращает базовую высоту. В конечном состоянии нет фиксированной высоты окна.

Единственный набор inputs/result и исходный state сохранены. Нет нового хранения, запросов или событий калькулятора. Введённые дополнительные параметры продолжают считаться после закрытия редактора. 400/34/44/30000 проверено как пользовательский сценарий: 136/176/+40 и 1 200 000 ₽/мес.; defaults не изменены. Формулы, единицы, отрицательные значения, запятая, ошибки и денежные оговорки сохранены.

Начальный desktop-переход `/#calculator` один раз выравнивается после загрузки шрифтов/разметки. Колесо, касание, клавиша или pointerdown отменяют это действие. Hook не обрабатывает последующие раскрытия, resize или ручную прокрутку. При переходе desktop→compact с фокусом в скрываемом поле фокус возвращается на «Изменить данные», без автоматического открытия редактора; raw value и selection сохраняются.

Использован текущий `outputs/tms-site`, а не архив старой версии. Git отсутствует; reset/clean/init не выполнялись. Изменения приложения: локальный `calculator-studio.module.css`, import/class в Calculator и B1Calculator, hook начального якоря и точечная передача фокуса. Shared CSS, helper B9, useLayoutMotion, кейсы, FAQ, Header/Hero/Footer, продуктовые темы, формы, маршруты, legal/consent/analytics/UTM, шрифты, package и lock не изменены. `lib/calculator.ts`, `lib/calculator-extension.ts`, `content/calculator-spec.json` и тексты B9 калькулятора сохранены побайтно.

Два старых теста адаптированы строго под новые требования: B1 больше не запрещает появление следующего заголовка после естественного desktop-калькулятора; B7 проверяет возврат фокуса на инициатор закрытого редактора вместо его автооткрытия. Остальные утверждения сохранены. Новые B10-проверки отдельно требуют стабильности baseline и роста/возврата геометрии раскрытий. Исходные тесты и before hashes доступны в snapshot; эти исключения явно отражены в source-audit. Генерируемый tsbuildinfo в ZIP не включён.

## Первые прогоны и исправления

Первый B10 browser: 31 PASS/1 FAIL — no-JS locator.click не дождался стабильного положения во время начального перехода. Проверка выполнена заново нативной клавиатурой после загрузки; 33/33 PASS. Первый общий прогон: 184 PASS/1 FAIL — прежнее требование скрывать следующий заголовок противоречило B10; изменено только это утверждение. Первый stability: 165 PASS/2 FAIL — известный Hero overflow и timing-sensitive промежуточный кадр неизменённого кейса при одновременных браузерных задачах. Последовательный повтор: 166 PASS / только известный Hero FAIL; первоначальные отчёты сохранены в `qa/v6-b10/first-run`.

Первый запуск unit в sandbox не смог открыть localhost для существующего тестового upstream; после разрешённого локального запуска все 70 PASS. Первый тестовый config общей регрессии имел несовместимый import.meta в CJS; исправлен на разрешение пути относительно __dirname, без изменения приложения.

## Ограничения

- Native Safari — NOT RUN. Новая попытка SafariDriver вернула `session not created`: необходимо вручную включить “Allow remote automation” в Safari Settings. Настройки Safari не менялись.
- Физические iPhone/Android, аппаратная клавиатура телефона, VoiceOver и настоящий browser zoom 200% — NOT RUN. Chromium viewport/media emulation и CSS text200 не названы проверками этих устройств/режимов.
- Известный общий Hero overflow 320→321 CSS px при сочетании text200/spacing/forced-colors остаётся. Глобальный overflow скрытием не маскировался.
- При низком окне и длинном результате/раскрытии часть инструмента ниже viewport, доступна обычной прокруткой; H2/верх не пересчитывают центр. Другие секции не подгонялись.
- Публичного deploy, реальных заявок, изменений секретов, платных сервисов, включения аналитики нет. Внешние условия выпуска не считаются закрытыми.

## Поставка

`TMS_V6_B10_source.zip` — полный чистый source. `TMS_V6_B10_patch.zip` — изменённые/добавленные файлы с before/after SHA-256, без удалений; конфликтный target останавливает применение до первой записи. `TMS_V6_B10_review.zip` — этот отчёт, source-audit, свежие кадры, видео, галерея и фактические результаты. Сырые traces исключены из ZIP, поскольку могут содержать ответы ресурсов со шрифтами; они остаются в локальном QA.

В source нет env/секретов/node_modules/.next/QA/внутреннего пакета/файлов шрифтов. Авторские локальные шрифты в рабочем проекте сохранены. В извлечённой чистой копии используется существующий закреплённый @fontsource bootstrap. Отдельная проверка извлечения фиксируется в `qa/v6-b10/extracted-source-verification.json`; SHA-256 всех payload проверяется до сборки. Зависимости проверяются на существующей установленной версии из того же lockfile, без заявления о новой сетевой установке.

## Источники реализации

Внутренний B10-пакет прочитан отдельно от приложения и не включён в поставку. Все 4 референса просмотрены. CSS/readiness инструкции прочитаны в установленной документации Next 16.3.8. [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) использован для границ общего blur/fallback, [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) — для проверки адаптации. Страницы Apple HIG Materials/Layout через web-инструмент вернули JS-only; числовые параметры Apple не приписывались. Композиционные ориентиры взяты из задания владельца, не представлены как нормы Apple.
