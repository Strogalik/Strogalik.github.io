# Решения V5

6 октября 2026. Реализация продолжает V4, а визуальная иерархия опирается на V3 и TMS. Это предложенная веб-адаптация, не официальный нативный стандарт Apple.

## Сайт объясняет, демо позволяет действовать

ProductPreview рендерится сервером, не импортирует reducer/seed/операционные компоненты и не содержит кнопок/полей. Hero показывает связь контекста продажи и исполнения. CRM иллюстрирует историю и следующий контакт, OMS — последовательность задач. Точный оффер и CTA сохранены. Отдельный unit-тест проходит граф импортов маркетинга; браузер проверяет отсутствие рабочего UI в DOM.

Главная показывает три продукта и три кейса без обязательных вкладок/свайпа. Navy-блок объясняет общий контекст короткой текстовой цепочкой. Калькулятор, шаги подключения, FAQ и финальный CTA завершают чтение. Подключение не обещает выдуманные сроки/цены. Подробные страницы сохраняют смысл и ограничения публичного содержания.

Общий root layout остаётся один: metadata, fonts, LeadProvider, Analytics и skip-link. Route group `(marketing)` добавляет только нужные Header/Footer. `/demo` не становится внешним сервисом; большая маркетинговая шапка, промо-Hero и footer там отсутствуют.

## Роли и композиция

CSS пересобран по ответственности: основа → маркетинг → формы → демо → адаптация. Удалён прежний V3/V4 хвост конфликтующих правил; новые !important overrides не добавлены (кроме стандартного hidden и reduced-motion). Основной текст — 18px/rem на desktop/mobile, lead 21/18, H1 52–64/38, H2 36–44/30, H3 24–26, значимые пояснения/контролы — 16. В демо смысловой текст — 16; 14 только вторичные ID/даты.

Контент ограничен 1280px, поля 48/32/20px. Интервалы основаны на шкале 4/8/12/16/24/32/40/48/64/80. Между неокрашенными группами контролируется общий разрыв 80px desktop / 48px mobile; eyebrow входит в группу заголовка. Окрашенные полосы имеют собственные внутренние поля. Hero не имеет 100vh; короткий laptop сохраняет тот же размер текста. Продукты/кейсы используют subgrid для одинаковых базовых линий; на узком экране — вертикальные карточки. Исходный логотип пропорционален.

Шрифты не заменены. CDP подтвердил реальные custom glyphs кириллицы; внутреннее PostScript имя оригинального Montserrat осталось Thin, но OS/2 исходного WOFF2 имеет weight 700, а заголовки запрашивают 700. Это имя не интерпретируется как фактический тонкий кегль. В чистом ZIP действует закреплённый npm fallback; его собственная сборка и runtime проверяются отдельно.

## Демо и состояние

DemoShell читает allowlisted query. Виды/контуры меняют URL без product-view key и потери модели. Versioned sessionStorage содержит только синтетические данные с Zod-проверкой; общий reducer восстанавливается из журнала. Корзина/заказ и расписание школы имеют отдельные проверенные хранилища, поэтому переход между тремя сценариями не теряет изменения. Некорректный storage/запрет доступа дают fallback, пределы описаны в README. Явный сброс восстанавливает свой сценарий.

Доска — flex-полоса колонок с локальной горизонтальной областью, всегда в одном ряду. Поиск ищет также связанные задачи. Деталь — native modal dialog: focus trap, Escape, возврат к карточке; desktop overlay не перестраивает канбан. Изменить этап, назначить и выполнить можно без drag-and-drop. Сводки производные.

Mobile без явного вида получает список. Табы контуров компактны, вид выбирается через доступный select, фильтры свёрнуты и показывают число условий. Agenda линейна; явная доска остаётся локальной полосой. Панель записи занимает 100dvh и учитывает safe-area; основной документ не маскирует overflow. При первом проходе обнаружена и исправлена ранняя history.replaceState, которая не обновляла mobile view после гидратации: начальный default меняется через Next router.replace. Дополнительно SSR готовит мобильный список через CSS до гидратации, место toolbar зарезервировано сразу, а свёрнутые панели не раскрываются на один кадр. Это устранило измеренный CLS начальной загрузки демо; явный board URL остаётся доской.

## Источники и пределы

Основы читаемости и адаптации дополнительно сверены с официальными [Apple Typography](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/typography.json), [Apple Layout](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/layout.json), [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) и [Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html). Конкретные веб-кегли заданы заданием TMS; нативные pt не переносились в CSS px.

CRM-конкуренты использованы через предоставленное исследование информационной структуры; их сайты не объявлены вновь измеренными по всем состояниям. Не перенесены чужие тарифы, счётчики, брендинг, SF или обещания. Исторические кейсы и их оговорки неизменны; учебные действия не доказывают состав любого тарифа.
