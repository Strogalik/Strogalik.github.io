## Что сохранено

Десктопный Hero сохраняет H1, оффер, двухколоночную сетку, масштаб, оригинальный логотип, Montserrat/Inter, фирменную палитру и все роли кнопок. Изменения относятся к внутренним материалам и контролам. Тёмный компактный футер сохранён; убран декоративный знак внешней ссылки. Служебные образцы перенесены после футера, чтобы не разрывать композицию.

Главная V5, `/demo`, кейсы, калькуляторы, lead API и его ограничения, контакты, зависимости и lockfile не изменены. Gate и исключение review из аналитики/UTM сохранены побайтово. Этап B не начат, настоящих отправок и deploy не было.

## Hero: материал, управление, mobile

Внешнее окно и его цветная подложка остаются близкими к A1. Убраны тень внутреннего окна и карточки исполнения, белая вложенная карточка договорённостей заменена открытой записью с одной тонкой линией. У сообщения менеджера больше нет массивного яркого канта и дополнительной тёмной плашки.

**Новое локальное решение A2:** Sapphire / 8% поверх белого для исходящего сообщения, текст Navy. Это изменение применения материала, а не замена исходного токена: `--tms-message-outgoing` остаётся исходным градиентом. Цвета кнопок и авторские значения стекла не менялись. Обычный текст сообщения: минимум 17,353:1 на desktop и 17,321:1 на mobile. Подпись на прозрачном участке переведена в Navy после измерения недостаточного контраста серого; итог 6,219:1 / 6,871:1.

Декоративные стрелки удалены из CTA, caption, раздела и футера. Одна кнопка с локальным SVG меняет назначение: pause / resume / replay. Рядом капсула четырёх реальных фаз. Один clock одновременно управляет раскрытием и progress: 4,2 секунды, один самостоятельный цикл при появлении первого смыслового элемента. Пауза сохраняет точное время и положение; resize не сбрасывает её. Скрытие документа отменяет кадры, продолжение исключает время невидимости. Повтор создаёт один новый цикл. Reduced-motion сразу показывает финальную историю; включение настройки во время цикла безопасно завершает движение.

На mobile сохранён H1, пояснение сокращено до той же сути; основная кнопка стоит перед историей. Вторичная ссылка и подпись встречи перенесены ниже. На реальных 390×844 и 430×932 первое сообщение целиком читается в первом viewport, видна его связь с договорённостями. На 320/360 и при увеличении текста композиция свободно растёт. Нет нижней fixed CTA и масштабирования всей картинки.

## Вместо карусели — один рассказ

До взаимодействия названы все три направления и их роли. Desktop: один вертикальный список из шести тем, сгруппированных по CRM, OMS и разработке. Mobile: три компактных направления и только две темы активного направления, затем заголовок и визуал. Нет второго счётчика, breadcrumb, длинной полосы, dashboard, fake CRM-операций или новых модальных слоёв.

| Тема | Что раскрывает объект |
| --- | --- |
| Клиентская история | Разворот объединяет историю общения и выделенный фрагмент договорённостей — общий контекст для команды |
| Следующее действие | Выразительная закладка переносит внимание на продолжение разговора: следующий контакт и ответственность |
| От продажи к исполнению | Тот же мотив договорённостей связывает коммерческую и операционную стороны одного листа |
| Работа команды | Цельный складной лист показывает задачи, сроки и ответственность как части исполнения; на телефоне это единая вертикальная композиция |
| Начинаем с процесса | Проектный разворот задаёт вопросы об участниках, данных и нужном результате |
| Подбираем решение | Готовая основа CRM/OMS и отдельное продолжение под процесс компании; это иллюстрация состава, не конструктор |

Смена темы синхронно меняет заголовок, текст, объект, пояснение и ссылку. Нет автоматической смены тем. Стрелки клавиатуры перемещают фокус, Enter/Space активируют тему; Tab переводит в панель. Выбор сохраняется при resize. Пояснения открываются в одном native details внутри сцены и не требуют ухода со страницы. Форма возвращает фокус инициатору и сохраняет выбранную тему и положение страницы. Ссылки на продукты/кейсы вторичны к разговору с командой.

Без JavaScript остаются финальная Hero-история, объяснение предложения, первая визуальная сцена и шесть native раскрытий с обычными ссылками. Недействующие кнопки скрыты; сообщение объясняет ограничение. На JS-версии форма по-прежнему проверяет только локальное заполнение и явно говорит, что обращение не отправлено.

Контраст проверяется по реальному составному фону: только на время измерения текст прозрачен, затем его стили восстанавливаются; PNG анализируется локально. Метод не является полной сертификацией WCAG. Фоны сцен и ключевые состояния также просмотрены визуально.

До правок снят A1 в текущей среде на 1920, 1440, 390 и 430px и продуктовый экран 1920; это новые before-снимки, а не выдача старого PASS за новый. Снимки `*-mobile-full` расширяют только высоту окна для захвата всей секции; они не заменяют обычные hero-390/430.

Исправленные при QA дефекты: разрастание разворота при увеличении текста и недостаточный контраст подписи на прозрачном фоне. Финальные проверки повторены после исправлений.

## Ограничения среды

Playwright WebKit не установлен. Native Safari-проверка не выполнена: управление Safari было прервано, отдельное тестовое окно не подтверждено, пользовательское окно оставлено без дальнейших действий. Физические устройства и экранный диктор не проверялись.

Настоящий zoom 200%/400% — NOT RUN: стандартная команда увеличения во встроенном браузере не изменила измеренные viewport/DPR, поэтому результат не назван browser zoom. Выполнен отдельно обозначенный reflow: 640 CSS px + root font-size 200%, line-height 1,5, letter-spacing 0,12em, word-spacing 0,16em. Проверка скрытой вкладки — симуляция visibility API, не отдельная проверка фоновой вкладки физического браузера.

Внешние сайты в A2 заново не проверялись: для шести сцен достаточны предоставленные локальные источники. Предыдущий доступ к Auto/Realty остаётся историческим фактом A1. Полный этап B, Lighthouse и настоящая доставка не запускались.

## Запуск и выдача

Из корня рабочего `tms-site`:

```sh
npm run build
node scripts/review-v6.mjs
```

Отдельный временный gate-off стенд для теста 404:

```sh
TMS_DESIGN_REVIEW=0 TMS_HOST=127.0.0.1 PORT=3201 LEADS_WEBHOOK_URL='' LEADS_WEBHOOK_TOKEN='' LEADS_LEGAL_APPROVED=false npm run start
npx playwright test -c playwright.v6.config.ts
node scripts/contrast-v6.mjs
python3 scripts/contrast-v6.py
node scripts/capture-v6.mjs
```

Не запускать несколько capture/test процессов одновременно. Сервер review остаётся loopback-only; его нельзя использовать как публичную авторизацию через proxy. Новые scripts/config пишут в `qa/v6-a2`, прежний `qa/v6` сохранён.

`TMS_V6_A2_review.zip` содержит новые материалы согласования. `TMS_V6_A2_patch.zip` — только фактические изменения относительно сохранённого A1, с хешами before/after и инструкцией. Это **не полный сайт**; рабочий проект уже обновлён, применять patch к нему повторно не нужно. Бинарники шрифтов, секреты, зависимости и внутренний пакет в patch не входят.

Следующая точка — утверждение владельцем показанного A2 или его правки. Агент не меняет статус на approved и не начинает B самостоятельно.
