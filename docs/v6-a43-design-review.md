## Результат

Рабочая база — существующий tms-site, /review/v6. Актуальное задание прочитано из PROMPT_FOR_CODEX_TMS_V6_A4_3.txt, пакет отдельно в work. Его scope, visual direction, code map, acceptance, evidence index, Apple findings и первые пять источников прочитаны. Открыты четыре главных before-снимка. Известный subset A4.2 совпал: 14/14 хешей, включая HeroStory и review.module.css. Сохранён полный локальный снимок 167 исходных/служебных файлов, без зависимостей и сборки. Git-репозитория в рабочем каталоге нет; reset/clean не выполнялись.

### Hero

Удалены artField и обе orbit из DOM/CSS. Вместо голубой округлой подложки — отдельный heroLight с радиальным светом и затуханием до прозрачности по всем границам. Единственный внешний контур — glassWindow: белая заливка 48%, Powder-кромка 40%, локальный блик 1px, одна тень 0 12px 32px Navy 7%, blur 16px/12px. Это локальные предложенные роли, авторские исходные токены сохранены.

Внутренние сообщения остались обычными заливками: Navy входящее, светлое исходящее, белая передача. Вложенного backdrop-filter нет. Clock, reveal, pause/resume/replay, H1, CTA, размеры и порядок Hero не менялись. Никакой новой opacity на группе с текстом. Bench обновлён под фактический материал. Непрозрачный Paper включается без поддержки blur, через QA data-no-blur, при повышенном contrast и reduced-transparency. Forced colors использует системные цвета. Поддержка системного ползунка iOS не обещается; это CSS-адаптация TMS, не системный Liquid Glass.

### Периферия второго раздела

Один статичный SVG для всех шести тем: плавная лента, две тонкие кромки (1.5/1px), слабый Sapphire-свет. Без текста, данных, стрелок, иконок и таймера. Слой aria-hidden, SVG focusable=false, pointer-events:none. Только декоративная область имеет mask/clip; родитель текста не маскируется. Свободный промежуток меню–текст сохранён. На ширинах ≤1250px декор отсутствует; на mobile дополнительной высоты нет.

Ширина слоя ограничена одновременно свободной периферией и пределом 480px. На проверенных desktop краевая область отделена от copy минимум на 24px; автоматическая проверка проходит все шесть раскрытых тем. Отключение слоя не меняет прямоугольники copy/меню/intro и scrollHeight. Визуальное качество оценивается по снимкам, не выдуманному pixel-diff критерию красоты.

### Mobile

Вместо grid 1fr/1fr/1.5fr и трёх длинных линий — content-width flex-капсула с переносом, max-width:100%, нейтральной непрозрачной основой и одним белым выделенным сегментом с Sapphire-контуром. Контур выбранного состояния использует тот же контрастный Sapphire, что и текст выбора, вместо слабой промежуточной голубой обводки. Полные CRM / OMS / Разработка, шрифт 16px, нажимаемые области ≥44px. Desktop topics не изменены.

aria-pressed, выбранная тема, две темы направления, стрелки/Home/End/Enter/Space и обе защиты фокуса A4.2 сохранены. Выбор мгновенный. При 200% текста допускаются дополнительные строки. Для найденного overflow на 320px также разрешено сжатие/перенос существующим contextStrip и образцу материала; служебная метка версии в шапке теперь может переноситься. Обычная шапка и её hover/CTA не изменены.

## Найденные края и исправления

Первый прогон: 36 PASS / 2 FAIL. На 1728px область декора начиналась на 11.19px левее правого края copy; изменён предел ширины независимого слоя, не сетка. На 320px при 200% тексте обнаружено переполнение существующих contextStrip/bench/метки шапки; добавлены min-width:0 и переносы. Новый тест остался строгим. В первом Hero-render был виден прямоугольный край градиента; добавлено радиальное затухание. Эти начальные снимки и initial-browser.log сохранены отдельно. При финальном просмотре отдельно уточнены затухание фона bench и видимость полос меню в forced-colors; их снимки обновлены, полный browser suite повторён. Прочие снимки соответствуют неизменившимся областям финального рендера. Ещё один полный повтор выявил старую гонку resize → Home: React media-store мог ещё содержать desktop-режим после CSS-перехода на mobile. Keyboard-handler теперь читает matchMedia в момент события; список видимых тем сразу соответствует CSS. Обе защиты blur/resize сохранены. Неудачный прогон записан в resize-keyboard-regression.log; после исправления выполнена серия из 10 повторов этого сценария и полный набор.

## Первичные источники и границы

[Apple iOS](https://www.apple.com/os/ios/) — акцент на читаемости и контрасте; [Meet Liquid Glass, transcript Principles](https://developer.apple.com/videos/play/wwdc2025/219/) — избегать стекла поверх стекла. [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) и [Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls) прочитаны через официальные JSON endpoints. HIG рекомендует обычные поверхности для содержания и обычно одинаковую ширину сегментов; наша неодинаковая content-width группа — явно TMS-решение для русских названий. [iPhone Duo](https://www.apple.com/iphone-duo/) изучен по структуре разделов и выбора представления. Видео целиком не проигрывались, нативные Apple API/ассеты/шрифты не переносились.

Playwright WebKit попытались запустить: бинарный файл недоступен. Реальный Safari, физические устройства, screen reader и настоящий browser zoom не запускались. CSS font-size 200% не равен browser zoom. Предпочтения contrast/forced-colors/reduced-motion эмулированы Chromium. Нет заявления о production-ready по одному Chromium.
