## Результат

На главной сохранены принятые Header, Hero, история и шесть тем. Затем добавлены три кейса, один калькулятор с двумя режимами, порядок сотрудничества, FAQ и финальный CTA. Собраны `/products/crm`, `/products/oms`, `/products/crm-oms`, `/cases`, три прежних case-slug, `/custom-development`, `/about`, `/partners`, `/privacy` и 404. `/demo`, sitemap/robots и 308 с `/products/brm` сохранены. Основное действие — разговор с показом реальной системы; учебное демо вторично.

Закрытый `/review/v6` и его компоненты остались эталоном. Обычные страницы используют минимальный слой `components/site-v6`, прежний CSS и motion. Public Hero всегда CSS; query `glass=sdk` не включает GPU или diagnostics. Старый глобальный LeadProvider удалён из root, действующий provider ограничен SiteShell; дублирования Header/Footer/Dialog нет. Все технические отличия перечислены в approved-component-map.json.

Форма сохранена визуально и подключена к `/api/lead`. Новая совместимая ветка consultation принимает обязательные имя/контакт/согласие и необязательные компанию/задачу; валидирует контекст/slug. Старые четыре intent сохранены. Реализованы pending, ошибки, timeout, retry, UTM, focus trap/restore. Исправлена особенность Safari: при клике кнопка может не стать activeElement; возврат фокуса теперь использует реально нажатую кнопку. Реальных заявок не отправляли.

Калькулятор использует неизменные базовые модели. Дополнительные поля сценарной выручки и стоимости времени вынесены отдельно. Пустое значение не превращается в ноль, дроби/запятая/отрицательная дельта сохраняются, переполнение проверяется. Нет смешения выручки, прибыли и оценки времени.

## Что мешает полному закрытию

При 1440px и одновременных text 200%/увеличенных интервалах замороженный footer расширяет документ до 1475px. Это воспроизводится и на нетронутом A4.8. Предложение `proposed-accessibility-fix.patch` меняет только перенос длинных контактов; browser-only probe возвращает ширину 1440px. Оно **не применено**: текущий запрос запрещает менять принятые компоненты без показа необходимого отличия. После разрешения требуется повторить обычный pixel diff и accessibility-проверку. Другие участки продолжены и завершены.

Перед публичным запуском необходимы полный юридический текст/оператор/условия обработки, настройка и проверка реального delivery endpoint в целевой среде, production origin/индексация и схема размещения с сохранением `/auto/` и `/nedv/`. Эти два существующих внешних адреса ответили HTTP 200 при read-only проверке; сервер владельца не менялся. Дизайн-утверждение не является юридическим разрешением. Никаких deploy, реальных отправок, платных сервисов или изменений секретов не было.
